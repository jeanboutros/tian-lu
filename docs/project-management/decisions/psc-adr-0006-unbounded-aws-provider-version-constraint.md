# ADR psc-adr-0006: Unbounded AWS provider version constraint

## Status
Accepted

## Context

CH-LZ-009 identified provider version constraint divergence across stages:
- `infra/_common/versions.tf:15-18`: `aws >= 5.95.0, < 7.0.0` (upper bound)
- `infra/live/10-management-iam/providers.tf:5-8`: `aws >= 6.56.0` (NO upper bound)

The user decision recorded in A0-task-definition.md:44 was explicit: "CH-LZ-009: >= 6.56.0 with NO upper bound."

However, SPEC-SW-010 (D-1) proposed `>= 6.56.0, < 7.0.0` with an upper bound, contradicting the user decision. The challenger identified this (D-1, M-1, R-1) and the user ruled to resolve it per the A0 decision.

The security concern with an unbounded upper constraint (`>= 6.56.0` with no `< 7.0.0`):
- A future AWS provider 7.x major release could be auto-selected by Terraform
- Breaking changes in 7.x could silently alter IAM policy serialization or resource behavior
- The policy text reviewed under provider 6.x may not match what provider 7.x generates — a silent policy-drift vulnerability

The trade-off: upper bounds prevent silent drift but require manual updates; no upper bound risks silent major-version upgrades.

## Decision

1. **Provider constraints unified to `>= 6.56.0` with NO upper bound** — matching A0:44 user decision
2. **Supply-chain risk documented as gaps-register advisory**, not an acceptance criterion
3. **Dependabot docker ecosystem added** (R-43, D-21) to track Floci image tag drift, but provider version drift is tracked separately
4. **All stages use the same constraint** — `_common/versions.tf` is the source of truth, stage providers reference it

## Consequences

**Enables:**
- Automatic patch/minor updates from AWS provider (security fixes, new resources)
- Single source of truth for provider version across all stages
- Consistent with user's explicit A0 decision

**Trade-offs:**
- Major version upgrade (6.x → 7.x) could be auto-selected
- IAM policy JSON generated by 7.x may differ from 6.x — silent policy drift risk
- Must monitor provider releases and test explicitly before major upgrades
- Supply-chain risk advisory in gaps-register, not a blocking gate

**Mitigations:**
- `terraform validate` in CI (SPEC-DO-017, M-23) catches syntax breaks
- G6 negative test (SPEC-SW-015, CH-LZ-002) catches IAM evaluation changes
- Manual review of `terraform plan` before major provider upgrades
- Dependabot alerts for provider version changes (if configured for Terraform)
